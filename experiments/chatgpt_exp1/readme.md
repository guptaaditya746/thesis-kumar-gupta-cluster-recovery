## Key Concerns

1.  **LLM Output Consistency**: The responses generated by the LLM are currently non-deterministic (e.g., missing brackets, inconsistent terminology). This randomness makes direct database querying unreliable. Ensuring syntactical correctness and consistency is a critical issue to resolve.

2.  **Logging and Debugging**: A dedicated logging system is necessary to capture raw LLM responses and pipeline states. This is essential for debugging and analyzing failure modes.

3.  **Infrastructure Optimization**: While the current `sbatch` script is functional, it requires optimization to improve efficiency and resource management.

4.  **Artifact Scope**: The project involves a large-scale implementation: processing ~60,000 research papers, defining the ontology, and designing the database schema.

5.  **Framework Selection**: We need to clarify the benefits of incorporating specific LLM frameworks. The priority is to utilize open-source solutions where possible to maintain control and reproducibility.

6.  **Pipeline Architecture**:
    *   **Workflow**: 60k Papers $\rightarrow$ Parsing $\rightarrow$ Intermediate JSON Storage $\rightarrow$ Ontology Mapping $\rightarrow$ Schema Design $\rightarrow$ Knowledge Graph Population.
    *   **Database Constraints**: Can we rely solely on Neo4j for this purpose? We need to identify potential limitations regarding scale or query complexity.
    *   **User Interaction**: The system must handle complex natural language queries (e.g., "What datasets were used in the last 10 years by authors from the Webis department for entity recognition tasks?"), convert them into structured queries (Cypher/SPARQL), and retrieve accurate results.
